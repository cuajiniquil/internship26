\begin{abstract}

% PART I
Phylogenetic tree manipulation is essential to evolutionary biology and epidemiology.
This study presents a survey and benchmarking of 8 phylogenetic packages and tools,
evaluating their performance on tree traversal operations (preorder, postorder, level-order) and ultrametricity checking.
The tests were conducted on randomly generated trees of 1,000 leaves.
The performance metrics were measured in R-based (\ape, \castor), Python-based (\dendropy, \cogent, \biopython, \ete, \toytree),
and Julia-based (\phylo) tools.
% PART II: in comment
Subsequently, the best tools were selected and a coalescent likelyhood framework was constructed around them, which has several 
real-world applications, such as epidemic outbreak modelling.

\end{abstract}

\section{Introduction}

Phylogenetic trees are data structures used in evolutionary biology, representing the evolutionary
relationships between taxa. Modern phylogenetic studies frequently involve large trees (thousands to millions of leaves),
which requires efficient algorithms to manipulate said trees.

% PART II: 
% Additionally, in epidemiology, birth-death processes provide a framework for estimating transmission parameters
% and the number of unsampled individuals during disease outbreaks. These models require extensive tree traversal and
% statistical inference, making computational efficiency crucial.

Current phylogenetic software is remarkably diverse, with implementations avaliable across multiple programming languages. 
While many studies focus on phylogenetic inference accuracy, comparative performance evaluation of fundamental tree operations is limited.

This report addresses two key objectives:
\begin{enumerate}
    \item Benchmarking basic tree operations across several phylogenetic packages

\end{enumerate}

\section{Methods}

\subsection{Part I: Tree Traversal Benchmarking}

\subsubsection{Benchmark Design}

A standardized benchmarking framework was implemented to evaluate four core operations:
\begin{itemize}
    \item \textbf{Preorder traversal:} Root-to-leaf depth-first search (DFS) (fig.1A)
    \item \textbf{Postorder traversal:} Leaf-to-root DFS (fig.1B)
    \item \textbf{Level-order traversal:} Queue-based breadth-first search (BFS) (fig.1C)
    \item \textbf{Ultrametricity checking:} Verifies that all leaves are equidistant from the root (fig.2)
\end{itemize}

% FIGURE 1A, 1B, 1C : shows preorder, postorder and level order traversal on the same tree

% FIGURE 2: shows ultrametric (left) vs heterochronic (right) tree

\subsubsection{Tree Generation Procedure}

Test trees were generated in ape using coalescent models of 1,000 and 10,000 leaves:
\begin{itemize}
    \item Ultranetric trees: rcoal(n) generates a coalescent tree of n leaves
    \item Heterochronic trees: rtree(n) generates a general tree of n leaves
\end{itemize}

For each tree type and size, 1,000 trees were generated and stored in nwk files. 

\subsubsection{Benchmarking Procedure}

Timing measurements followed a warmup iteration to account for JIT compilation and memory allocation overhead. 
Execution times were recorded in microseconds.

\subsubsection{Tools Evaluated}

\paragraph{\ape} (R package)

Framework: \ape is the foundational R package for phylogenetic analysis. It provides native tree data structures
using edge lists stored in $n \times 2$ matrices. Tree operations are implemented in compiled C code for performance.
The package includes native R plotting via base graphics. Benchmarks use the \texttt{is.ultrametric()} function
from the compiled backend.

\paragraph{\castor} (R package)

Framework: [TBD] Specialized R package for tree inference and analysis. To be documented.

\paragraph{\dendropy} (Python)

Framework: Pure Python implementation of phylogenetic data structures. \dendropy uses object-oriented design with
Node and Tree classes. Traversal algorithms are implemented in Python, relying on recursive depth-first and
iterative breadth-first approaches. No compiled backend; performance bottlenecked by Python interpreter overhead.

\paragraph{\cogent} (Python)

Framework: \cogent is designed for comparative genomics with phylogenetic capabilities. Implementation strategy
prioritizes code clarity over raw speed. Includes optional Cython compilation for performance-critical sections.
Tree operations leverage NumPy-based array operations where applicable.

\paragraph{\biopython} (Python)

Framework: General-purpose bioinformatics package with phylogenetic submodule (\texttt{Bio.Phylo}). Provides
wrappers around external phylogenetic tools while offering native Python tree structures. Implementation emphasizes
compatibility with diverse tree formats (Newick, Nexus, PhyloXML) over computational efficiency.

\paragraph{\ete} (Python)

Framework: Pure Python implementation optimized for interactive phylogenetic analysis. \ete uses recursive tree structures
with lazy evaluation of some properties. Recent versions include compiled extensions for critical operations.
The library emphasizes usability and visualization (including ASCII display) alongside performance.

\paragraph{\toytree} (Python)

Framework: Lightweight Python tree library designed for rapid phylogenetic analysis. Implements core operations
in compiled C via Cython bindings, providing significant speedup over pure Python alternatives.
Integrates with Jupyter notebooks for interactive workflows.

\paragraph{\phylo} (Julia)

Framework: Julia package providing multiple dispatch-based tree implementations. Julia's LLVM JIT compilation
enables performance comparable to compiled languages. Tree operations are implemented in Julia with selective
use of optimized algorithms. Notable: substantial variance in performance indicates JIT warm-up effects across iterations.

\subsubsection{Statistical Analysis}

For each tool and operation, summary statistics were computed:
\begin{itemize}
    \item Mean, median, and standard deviation of execution times
    \item Min/max times to identify outliers and JIT compilation effects
\end{itemize}

Summary visualizations (violin plots, box plots) were generated for qualitative comparison.

\subsection{Part II: Birth-Death Model Benchmarking}

\subsubsection{Outline}

Birth-death processes model the transmission dynamics of epidemics, with birth rate $\lambda$ (transmission)
and death rate $\mu$ (removal/sampling). Given a phylogenetic tree of sampled individuals, inference of
$\lambda$ and $\mu$ estimates transmission rate and the proportion of infected individuals who were sampled.

Key challenges in benchmarking:
\begin{itemize}
    \item Large datasets: Real outbreak trees frequently contain $>100,000$ tips
    \item Sampling effects: Non-random sampling biases parameter estimates
    \item Computational scalability: Likelihood evaluation requires tree traversal and recursive computation
\end{itemize}

\subsubsection{Compiled vs. Interpreted Implementations}

\paragraph{High-Performance Tools (\cogent, \toytree)}

\cogent exhibits exceptional performance for traversal operations ($\sim 150-400 \mu s$),
likely due to algorithmic optimization or compiled extensions in critical sections.
\toytree also demonstrates strong performance ($\sim 1.8-2.1 \mu s$ for traversal, $\sim 5.8 \mu s$ for ultrametric check),
consistent with its Cython-based implementation.

\paragraph{Pure Python Tools (\dendropy, \biopython, \ete)}

\dendropy achieves moderate performance ($\sim 3.8-4.5 \mu s$), acceptable for interactive workflows but
substantially slower than compiled alternatives. \biopython exhibits variable performance: excellent
on ultrametricity checking ($\sim 3.5 \mu s$) but slow on traversals ($\sim 28 \mu s$). \ete shows
dramatic overhead on ultrametricity checks ($\sim 70 \mu s$), suggesting algorithmic differences
or missing optimizations in the implementation.

\paragraph{Julia (Phylo.jl)}

\phylo demonstrates moderate traversal performance ($\sim 289 \mu s$ preorder) with high variance,
reflecting JIT compilation warm-up costs. Postorder traversal is notably slower ($\sim 3 \mu s$),
indicating potential algorithmic inefficiency. The high variance (std. dev. $\sim 5100 \mu s$)
suggests that performance predictions are unreliable on first-run executions.

\section{Conclusions and Perspectives}

\subsection{Key Findings}

\begin{enumerate}
    \item \textbf{Substantial Performance Variation:} Performance differences exceed 400-fold across tools,
    emphasizing the importance of tool selection for computationally intensive phylogenetic analyses.

    \item \textbf{Compiled Backends Essential:} Tools with compiled implementations (\cogent, \toytree, \phylo JIT)
    outperform pure Python alternatives by 5--200$\times$.

    \item \textbf{Algorithm Choice Matters:} Identical operations show significant variance across implementations,
    suggesting different algorithmic approaches (e.g., \ete's ultrametricity check).

    \item \textbf{Language Trade-offs:} R-based tools (\ape) balance performance with extensive statistical capabilities.
    Julia shows promise but current implementations exhibit high variance, likely reflecting JIT overhead.
\end{enumerate}

\subsection{Recommendations}

\begin{itemize}
    \item \textbf{Interactive analysis:} \ete or \toytree for their visualization and usability
    \item \textbf{Performance-critical applications:} \cogent or \toytree for maximum throughput
    \item \textbf{Large-scale inference:} Compiled solutions (\ape with C backend) recommended
    \item \textbf{Future consideration:} Investigate Rust-based implementations (e.g., shiftcarb, phylo-rs)
\end{itemize}

\subsection{Future Directions}

\begin{enumerate}
    \item Complete benchmarking of birth-death process inference across tools
    \item Evaluate performance on real outbreak datasets (>100k leaves)
    \item Investigate memory usage and scalability limits
    \item Assess accuracy of parameter estimation under non-random sampling
    \item Profile code hotspots to identify optimization opportunities
    \item Explore hybrid approaches combining tools' strengths (e.g., Julia for inference, Python for visualization)
\end{enumerate}
